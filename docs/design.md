# 已确认设计与实施计划

日期：2026-09-22。独立项目：`E:\工作空间\codex-agent-manager`。

## 用户确认的范围

1. 仅管理 Codex 子代理，范围是原生 / Orca 托管 / 同时两套。
2. 编辑已有角色，支持新增和删除自定义角色。
3. 区分官方角色、官方角色覆盖、自定义角色；官方仅 GPT，自定义不限制模型厂商或名称，实际连通性测试通过才允许保存。
4. 本地 Web 操作，不要求启动 AI 会话。

## 实施

- Python 标准库 HTTP 服务，tomlkit 保留 TOML 格式；纯 HTML/CSS/JS，Lucide 图标，无前端构建链或数据库。
- app/config.py 读取与分类；connectivity.py 目标服务商请求；manager.py 预览、测试凭据绑定、事务与恢复；server.py 提供本地 API。
- web/ 提供两套配置差异、角色编辑、操作预览、连通性结果和恢复入口。
- 启动脚本复用已有进程，后台隐藏窗口；Git 仅初始化，提交需用户确认。

## 验收

- 原生单独修改不影响 Orca，反之亦然；双套只改变编辑字段。
- 新增、删除、恢复、官方覆盖和 GPT 限制均有自动化测试。
- 未测试、测试失败、凭据变更、文件冲突不允许保存；双套失败回滚。
- TOML 提示词、注释和未知字段不被无关覆盖；API 输出不包含认证材料。
- 本地模拟服务验证 Responses 成功、失败、无输出；浏览器覆盖主流程与窄屏。
- 真实配置仅只读抽查，测试目录自动清理。

## 已知边界

实际模型能力由服务商决定；不宣称连通即工具兼容。仅 API Key/Responses 认证，OAuth 刷新不在本版范围。Orca 后续启动同步与热加载不作未经实测的保证。保留现有非 GPT 的官方覆盖，修改时才校验。

## 分发场景补充

已确认补充首次目录检测、手动输入/本机文件夹选择、路径记忆。配置范围仍只有原生 Codex 与 Orca，可仅启用其中一种。设置保存在不入 Git 的 `.local/settings.json`。

settings.py 负责检测和持久化，Manager 在原锁内切换已校验目录并丢弃旧计划；备份按所属目录筛选。所有目录选择只读取 Codex 文件，保存设置不修改角色。浏览器测试覆盖首次设置、无效目录、单套启用、重新开启两套；单元测试覆盖不同用户根目录、环境变量及重启记忆。
